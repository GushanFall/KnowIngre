# 知食分子 KnowIngre

> 吃，是一门学问

轻量级智能厨房管理工具，支持 AI 生成菜谱、食材库存追踪、今日菜单规划。内置多用户系统和家庭共享。

## 功能

### 菜谱库
- AI 一键生成菜谱（输入菜名 → 自动填入食材和步骤）
- AI 微调修改（"换牛肉"、"减少用油"）
- 手动录入，支持标签分类、评分、搜索
- 20 种预设标签，AI 生成时自动选用，避免标签散乱
- 记录最近制作日期

### 食材库存
- 10 个分类（蔬菜、肉类、蛋奶、调料等）
- 智能匹配可制作的菜品，标注缺失食材
- 模糊匹配：「鸡胸肉」自动匹配库存里的「鸡胸肉」
- 做完菜后库存归零自动清理

### 今日菜单
- 采购清单：汇总所需食材，标注已有/缺货
- 做完自动扣减库存，标记制作日期
- 支持逐道确认或一键全部做完
- 全部做完时合并同一食材的用量，一起预览、确认并提交；中途失败会整批回滚
- 电脑端菜单与备料清单并排显示，手机端上下排列；优先展示待采购、数量不足和待确认项，已备齐的食材可展开查看
- 备料状态与实际扣减使用相同计算结果，复制和图片导出也保留这些状态

### 单位与库存扣减
- 库存保留你习惯的计量单位，菜谱可使用不同单位；克/千克/斤、毫升/升等按固定关系换算
- 个/袋/根等与重量之间，需要为具体食材确认换算，例如「1 个番茄 = 200 克」；保存后也能用于以千克计量的菜谱，个人与家庭规则分别保存
- 扣减保留小数，例如 100 克番茄可扣减 0.5 个，不会逐道向上取整
- 单位缺失、用量为“适量”或区间、没有换算规则、合计库存不足时，需要确认剩余量；也可明确选择“本次保持不变”
- 多道菜使用同一份库存时，只填写一次最终剩余量；确认前库存、菜谱或菜单发生变化，会阻止提交并提示重新确认
- 常备调料继续只检查是否存在，不扣减数量

### 烹饪足迹
- 累计次数、菜品数、本月次数和连续下厨天数
- 年度日历热力图、常做菜排行和标签分布
- 个人/家庭记录隔离，家庭记录显示操作者
- 可撤销误记的烹饪记录（不会自动恢复库存）

### 厨房灵感
- 悬浮入口打开厨房问答助手，支持连续追问
- 可智能参考当前个人/家庭库存，也可直接咨询食材做法
- 支持“现在能做什么”“鱼有哪些做法”“推荐一道新菜”等开放问题
- 对话不会自动修改库存或保存菜谱，回答确认后再由用户操作

### 家庭共享
- 个人/家庭双模式，数据完全隔离
- 邀请码加入，成员共同编辑菜谱和库存
- 单个菜谱或批量同步到对面范围

### 多用户
- 注册登录，bcrypt 加密
- 新密码至少 8 位；登录和注册接口带有基础频率限制
- 默认仅允许创建首个管理员账号；已有部署如需临时开放注册，可设置 `OPEN_REGISTRATION=1`
- 管理员可重置他人密码
- 数据 JSON 导入导出
- 管理员可在「设置 → 数据」下载完整 SQLite 数据库备份

## 本地运行

```bash
# 1. 安装 Bun
curl -fsSL https://bun.sh/install | bash

# 2. 启动
bun run server.ts

# 3. 打开
open http://localhost:3000
```

首次启动自动创建数据库。停止按 `Ctrl+C`，重启不会丢失数据。

也可以使用 `bun start` 启动、`bun run dev` 监听开发改动、`bun test` 运行测试，无需安装额外依赖。测试使用临时数据库，不会修改项目现有的 `data.db`。

## 数据库备份与恢复

管理员登录后，打开 **设置 → 数据 → 下载完整数据库（.db）**。下载的文件包含所有账号、个人和家庭数据、烹饪记录、单位换算规则、API 配置及数据库中的应用密钥，请保存在可信位置。普通成员仍可使用原有的 JSON 导入导出，处理当前个人或家庭范围的数据。

完整备份在服务运行时生成，使用 SQLite `VACUUM INTO` 创建一致快照，包含已经提交、仍在 WAL 日志中的最新数据。下载得到一个独立 `.db` 文件，无需配套 `.db-wal` 或 `.db-shm`。生成后会清理服务器临时文件；下载接口仅允许管理员访问，并禁止缓存。

完整数据库备份通过服务器文件恢复，不能使用页面上的 JSON 导入按钮。恢复步骤：

1. 停止 Bun 服务，确认没有其他进程连接数据库。
2. 将现有 `data.db`、`data.db-wal`、`data.db-shm`（若存在）一起移到安全目录保留。不要让旧 WAL 文件留在恢复后的数据库旁边。
3. 将下载的 `.db` 文件复制为项目目录中的 `data.db`，确认运行服务的账号有读写权限。如果配置了 `KNOWINGRE_DB_PATH`，请使用该路径。
4. 用原来的环境变量和启动方式重新启动 Bun，登录检查数据。使用环境变量配置的 `JWT_SECRET` 不在数据库中，需另行保留。

## 升级已有部署

单位换算和烹饪足迹功能使用非破坏性迁移。升级启动时会新增
`ingredient_unit_conversions`、`cook_history`、`schema_migrations`、`app_metadata` 表，并为库存增加用于并发保护的
`version` 列。现有菜谱和库存记录不会删除；历史上误存成 `1个` + `个` 的库存会安全规范化为 `1` + `个`。

```bash
# 1. 在旧服务仍运行时也可生成一致的 SQLite 备份
sqlite3 data.db ".backup 'data-before-upgrade.db'"

# 2. 更新项目文件（包括 backend/、frontend/ 和 unit-conversion.ts）

# 3. 重启；新表会自动创建
bun run server.ts
```

更新时保留服务器上的 `data.db`、`data.db-wal`、`data.db-shm`、备份和环境配置，不要用本地数据库覆盖。此次代码整理未改变数据库表结构或启动命令。除根目录文件外，务必上传 `backend/`、`frontend/` 两个目录。

如果 Nginx 用作反向代理，更新后需要重启 **Bun 进程**以加载新的后端代码，仅重启 Nginx 不会重启 Bun。Nginx 配置不变时通常无需重启；如果由 Nginx 直接提供静态资源，需同步上传新的 `frontend/` 文件，并确保 `.js` 使用 JavaScript MIME 类型。浏览器刷新后加载新页面。

旧菜谱中的 `200g`、`2个` 等文本会在扣减时即时解析，因此无需批量改写历史数据。
首次升级会把每份菜谱现有的 `cooked_dates` 逐条复制到 `cook_history`，原字段保持不变；迁移带版本记录，重复启动不会重复导入。
家庭范围的旧记录无法可靠判断当时由哪位成员完成，因此会显示为“历史记录”，之后的新记录会显示实际操作者。
旧备份中没有换算规则或足迹表时也可正常导入；新备份会一并包含已保存的食材换算规则和烹饪足迹。
备份导入采用单事务的安全合并：相同 ID 更新、新 ID 添加，其他现有数据保留，失败时全部回滚。

生产环境建议设置固定的 `JWT_SECRET`。未设置时，服务会在数据库中生成并持久化一个密钥，后续重启继续复用，避免用户会话每次重启都失效。

建议通过管理员流程或短时设置 `OPEN_REGISTRATION=1` 添加家庭成员，完成后移除该环境变量并重启服务。

AI 服务地址默认要求使用 HTTPS，且会阻止本机、私网和链路本地地址，避免把部署服务器当作内网代理。确实需要连接本机 HTTP 模型服务时，需同时显式设置 `ALLOW_INSECURE_AI_URLS=1 ALLOW_LOCAL_AI_URLS=1`，但不建议在公网部署时开启。

```bash
JWT_SECRET='请替换为足够长的随机字符串' bun run server.ts
```

## 使用流程

1. 注册账号（第一个用户自动成为管理员）
2. 设置中填入 API Key（默认 DeepSeek 接口）
3. 菜谱库新建菜谱，或输入菜名让 AI 生成
4. 库存中添加家中食材
5. 菜谱卡片点「加入菜单」，切换到今日菜单查看采购清单
6. 做完点「做完了」，库存自动扣减

│   ├── database.ts         # 建表、数据迁移和持久化密钥
│   ├── backup.ts           # SQLite 一致性备份与临时文件清理
│   ├── ai-prompts.ts       # AI 提示词

│   ├── cooking.ts          # 库存匹配与扣减计划
│   ├── cook-actions.ts     # 单道菜与整份菜单的事务提交和并发校验

│   └── static.ts           # 静态文件白名单
